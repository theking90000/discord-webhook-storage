# Discord webhook storage

Use Discord webhooks as file storage through a file-like asynchronous API.
Store files up to 20 MB and retrieve them with Range support and signed URL
renewal included.

## Installation

In `Cargo.toml`:

```toml
[dependencies]
discord-webhook-storage = "0.1.0"
```

## Basic usage

`WriteFile::open()` opens a new file for writing, much like opening a file on the
local filesystem. Discord assigns its identifier after the upload, so opening a
file does not require or accept a predefined ID.

`WriteFile` implements `futures::AsyncWrite`, so standard operations such as
`write_all()` and `flush()` work as they would with an asynchronous file.
`close().await` completes the upload without requiring a call to `finish()`.

`finish().await` closes the file if needed, checks Discord's response, and returns
a `WrittenFile` containing the message ID and attachment URL. After `close()`,
the upload has been sent even if `finish()` is never called; its ID and URL are
simply not retrieved, and Discord's response is not checked. Dropping a writer
without closing it does not complete the upload.

The caller establishes a TLS connection to `discord.com:443` and supplies a
transport implementing `futures::AsyncRead`, `futures::AsyncWrite`, and `Unpin`.

```rust,no_run
use discord_webhook_storage::{Result, WebhookCredentials, WriteConfig, WriteFile};
use futures::{AsyncRead, AsyncWrite, AsyncWriteExt};

async fn upload<T>(connection: T, webhook_url: &str) -> Result<()>
where
    T: AsyncRead + AsyncWrite + Unpin,
{
    let credentials = WebhookCredentials::parse(webhook_url)?;
    let mut file = WriteFile::open(
        connection,
        &credentials,
        &WriteConfig::default(),
    )
    .await?;

    file.write_all(b"hello from Rust").await?;
    let uploaded = file.finish().await?;
    println!("{}", serde_json::to_string(&uploaded)?);
    Ok(())
}
```

The default configuration uploads a file named `file.bin` and accepts up to
20,000,000 bytes. A write that would exceed this size fails without sending any
bytes from that call. Discord may enforce a different maximum file size.

`WrittenFile` supports Serde serialization and deserialization, with `id` and
`url` string fields, as shown above.

The included `webhook_upload` example establishes TLS with `tokio-tcp-pool`
and uploads 20,000,000 generated bytes:

```sh
DISCORD_WEBHOOK_URL='https://discord.com/api/webhooks/<id>/<token>' \
    cargo run --example webhook_upload --features tokio-tcp-pool
```

The optional `tokio-tcp-pool` feature enables the dependency used by this example.
The library accepts caller-supplied transports with or without this feature.
